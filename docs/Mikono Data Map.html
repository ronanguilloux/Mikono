Six rules the application enforces

They are what makes the reports reliable. Any new idea must say which of them it affects.

1. One row = one volunteer, one day

A group of five volunteers sent to a site is five activities. Batch entry creates them in one go, and it is all or nothing: if a single volunteer causes a problem, nothing is saved.

2. “Active” is not a checkbox

A volunteer is active when one of their stays covers today. Nobody has to update it, and it cannot be wrong. The trade-off: no stay, no activity entry.

3. The branch loop must close

An activity's project must be in the same branch as the volunteer's stay on that day. A volunteer staying in Mombasa cannot be logged on a Kibera project. This is the green loop in the diagram.

4. The program frames the task

The activity type must be one of those the program offers, and the date must fall within its dates (if it has any).

5. What has been used is never deleted

A volunteer, project, type, escort, user or branch already referenced somewhere cannot be deleted: the button is greyed out. You deactivate it instead, and the history stays intact.

6. Dates are days in Nairobi

No hours, no time zones: an activity takes place on a calendar day, Kenya time, even though the server is in France.

Four questions before adding a piece of information

A new request (“we'd also like to record…”) almost always comes down to these four questions. Their answers decide where it goes on the map, and therefore what it will cost.

What does it describe?

The volunteer (once and for all) or what they did that day (on every activity)?

Profession goes on the volunteer. The number of children seen would go on the activity, and would be entered every day.

Required or optional?

Required guarantees complete reports, but blocks entry when it isn't known.

That is why the last name became optional.

Fixed list or free text?

A list can be counted and filtered in the reports. Free text can be read, but not counted.

Activity types are a list; a volunteer's skills are free text.

Does it change over time?

If so, and we want the history, it needs dates (“from… to…”), like stays.

Otherwise, the old value is overwritten and lost.

Behind the scenes

Two lists exist outside the map because they are not about volunteers: sign-in attempts (email typed, success, IP address, erased after 90 days) and anonymous usage gestures (“a roster was copied”), which feed the admin-only Usage screen. They are never mixed: one is personal, the other must not be.
